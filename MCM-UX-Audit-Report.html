About this audit This report covers a full static analysis of the MCM Cloud CX prototype — a Genesys Cloud CX–style contact-centre admin console and agent workspace built as a training simulation. The application is a single React route that injects ~1.2 MB of vanilla JavaScript (14 functional engine modules) onto the page. The React component library (Radix UI / shadcn-ui) scaffolded by Lovable is present but not yet connected to the UI.

Findings are categorised by severity: Critical elements are completely broken or silent; High items significantly impact usability; Medium items cause friction but have workarounds; Low / Enhancement items are polish and polish improvements.

UX Dead-Ends & Navigation Gaps

Flows where users get stuck or lose context
🧭 Navigation & Routing Issues
1
Browser Back/Forward buttons don't work for sub-views

All sub-navigation (openPage, go) is DOM-only and does not update the browser URL. Clicking the browser's Back button navigates away from the app entirely instead of going to the previous admin page.

Use history.pushState() or history.replaceState() on each openPage() / go() call to keep the URL in sync.
2
Sidebar active indicator loses sync on breadcrumb navigation

Clicking a breadcrumb link (e.g. "Admin ›") re-renders content but doesn't update the .on class on the sidebar link. The highlighted item stays on the last-clicked page, creating a mismatch.

Call navMark(id) whenever content is loaded via breadcrumb or any non-sidebar path.
3
No deep-linkable URLs for any admin page

Sharing a URL to "People" or "Queues" is impossible — all traffic lands on the same blank login screen. Useful for training (sharing links to specific pages).

Hash-based routing (/#/admin/people) would enable deep links with zero backend changes.
4
No "Favourites" personalisation

The Admin index shows a "Favourites" tab but the list is hardcoded to ['people', 'queues', 'flows', 'campaigns']. Users cannot add or remove their own favourites.

Store favourites in localStorage and add a ★ icon to each admin card to toggle membership.
5
No empty-state messages in tables

Filtering a table to zero results leaves a completely blank table body — no "No results found" message. This looks like a loading failure to users.

Add a conditional empty-state row: "No items match your search. Clear the filter to see all results."

UX Improvement Suggestions

Design, interaction, and usability enhancements grouped by area
🎨 Button Design & Visual Hierarchy
High Impact
1
Primary vs secondary button distinction is too weak

The orange .btn (primary) and white .btn.sec (secondary) appear at the same height and font size. In dense page headers they can be confused, especially next to each other.

Increase secondary button border weight to 1.5px, reduce its font weight to 500, and add a subtle left margin between paired buttons.
2
Broken/placeholder buttons look identical to working ones

Buttons like "Export", "Preview", and "Debug" are styled identically to fully functional buttons. Users click, see nothing or a toast, and lose trust.

Apply opacity: 0.5; cursor: not-allowed; to all placeholder buttons, or wire them to real actions and remove the distinction entirely.
3
Destructive actions have no confirmation step

Deleting a user, queue, flow, or trunk happens immediately on a single click. There is no "Are you sure?" step. In a training environment this is especially risky as learners explore confidently.

Add a simple inline confirmation: change the button text to "Confirm delete?" for 2s before executing, or show a compact confirm dialog.
4
Top-bar icon buttons have no tooltips or labels

The 🔔 (notifications), ⊙ (what's new), and ? (help) icons are raw character glyphs with no accessible label. Users unfamiliar with the layout won't know what they do.

Add title="Notifications", title="What's New", and title="Help" attributes. Bonus: add a aria-label for screen readers.
5
Row action "⋮" menu hit area is too small

The three-dot overflow menu column is width:40px. Clicking it precisely on a high-density table is frustrating, especially on laptops with smaller trackpads.

Expand hit area to 48px minimum, or make the entire row show an action row on hover (à la Genesys Cloud's actual UI).
🗺 Navigation & Wayfinding
Medium Impact
6
No keyboard shortcut to focus global search

Enterprise tools (Linear, Notion, Salesforce) all use Ctrl+K / ⌘+K to focus the global search. Users who know this pattern will hit it instinctively and get no response.

Add a document.addEventListener('keydown', e => { if ((e.ctrlKey||e.metaKey) && e.key==='k') document.getElementById('gs').focus(); }) handler.
7
No collapsible admin sidebar

The left nav is always 246px wide. On a 1280px screen this leaves only ~1034px for content. A toggle to collapse to icon-only mode would reclaim meaningful horizontal space.

Add a collapse toggle button at the top of #anav. When collapsed, show only group-icon abbreviations with tooltips.
8
Global search Enter key does nothing

The dropdown with live results is functional and excellent. But pressing Enter to confirm a selection doesn't navigate — the user must click with the mouse.

Add keyboard navigation (↑↓ to highlight, Enter to navigate) to the search dropdown results list.
📋 Forms & Drawers
Medium Impact
9
No required-field indicators

Fields that are mandatory (queue name, person email, trunk URI) don't show an asterisk * or red border until after a failed save. Users don't know what's required upfront.

Add * to required field labels. On validation failure, add a red border + inline error message below the field rather than only a toast.
10
Long dropdowns have no search filter

Dropdowns like "Assign role", "Select queue", and "Choose flow" list all items as a plain <select>. With 50+ items (e.g. users list) scrolling to find a name is painful.

Replace long <select> elements with a searchable combobox pattern: an input + filterable <ul> positioned absolutely.
11
Drawer Save / Cancel buttons are not in a sticky footer

On long drawers (e.g. Queue editor with 5 tabs, People editor with roles/skills) the Save and Cancel buttons scroll out of view. Users must scroll to the bottom every time.

Give drawer footers position: sticky; bottom: 0; with a white/shadow backdrop so action buttons are always visible.
📊 Feedback, Data & States
Low–Medium Impact
12
No persistent notification history

Toast notifications (save confirmations, errors, alerts) auto-dismiss. The bell icon shows the last 8 audit entries, but a toast that disappears is gone. Users who miss one have no way to review it.

Add a "Recent notifications" section to the bell dropdown showing the last 10 toasts (type + message + time), persisted in window.DB.notifications[].
13
No loading / transition state

Switching between heavy pages (Performance dashboard, Architect editor) is instant but can feel jarring on low-end hardware. There's no indication that content is loading.

Add a 150ms CSS fade-in on #cnt content swap, and a thin orange progress bar at the top (similar to NProgress) during page transitions.
14
Data persistence is undiscoverable

The mcmExport() / mcmImport() functions let users save and restore their full DB state as JSON — but they're only accessible via the People page "Data" menu. New users will never find it.

Add a persistent "Save state / Restore" widget to the Admin index page, or expose it via the profile/avatar dropdown alongside Sign Out.
15
Column filter chips don't work on all pages

"Division: All ▾" and "Status: Any ▾" chips operate on pre-rendered static DOM. On pages backed by a live engine (People, Queues) they work; on static SNAP pages they filter the raw HTML text, which is unreliable.

Audit each page to confirm chip filters target the correct column index. For static pages, add a data-filter-col attribute so the generic chipFilter() handler can identify the right column.

Architecture Note

Observations on the current tech stack and unused components
📦 Unused React Component Library The project has a full shadcn/ui + Radix UI + Tailwind CSS component library installed (accordion, dialog, drawer, select, combobox, tooltip, and 40+ others). None of these components are currently used — the entire UI is vanilla JS injected via dangerouslySetInnerHTML.

Recommendation: These components could be used to replace the custom CSS patterns for drawers, dropdowns, tooltips, and confirmation dialogs. This would give the UI accessibility (ARIA roles, keyboard navigation, screen reader support) for free, since Radix primitives include it by default.
🏗 Component Library Adoption Opportunities
→
Tooltip (Radix)

Replace character-glyph icon buttons with <Tooltip> wrappers for instant accessible hover labels. Covers all top-bar icons and the "⋮" row menus.

→
AlertDialog (Radix)

Drop-in accessible confirmation dialog for all destructive actions (delete user, delete queue, delete flow). Blocks until the user confirms, preventing accidental deletes.

→
Command (cmdk)

cmdk is already installed. Replacing the custom #gs global search with a <Command> palette would give Ctrl+K, keyboard navigation, fuzzy search, and grouping for free.

→
Sonner (toast)

sonner is already installed. Replacing the custom toast system with Sonner would add toast types (success/error/warning/info), a notification queue, and programmatic dismissal.
